🔍 Inspect Element & Browser Developer Tools

The Inspect Element feature (DevTools) provides 6 core capabilities essential for web designers:

DevTools Core Capabilities

The 6 Essential Functions of Browser DevTools

  1. DOM & Element Inspection: Right-click any element on a page and choose Inspect (or press F12 / Ctrl+Shift+I). Inspect the live HTML hierarchy, node attributes, classes, IDs, and the CSS Box Model (margin, border, padding, content).
  2. Live DOM & CSS Manipulation: Add, edit, or delete HTML tags and toggle CSS declarations in real time. Modifications take effect immediately on screen without touching server files.
  3. JavaScript Console & Debugging: Log errors, output data with console.log(), set breakpoints in source scripts, step through line-by-line execution, and monitor variables in scope.
  4. Network Monitoring: Inspect every HTTP request and response, check status codes (200 OK, 404 Not Found, 500 Error), inspect request headers and payloads, and identify slow assets.
  5. Mobile Device Emulation: Toggle the responsive device toolbar (Ctrl+Shift+M) to simulate smartphones (iPhone, Samsung Galaxy), tablets, screen orientations, and 3G/4G network throttling.
  6. Performance Profiling & Auditing: Measure page load timelines, analyze frame rates (FPS), identify CPU bottlenecks, detect memory leaks, and run Lighthouse performance/SEO audits.

🏷️ Naming Conventions & Path Referencing

Convention Format Example Where to Use in Web Design Rule
kebab-case about-us.html, hero-banner.jpg File names, directory names, CSS class names Mandatory for URLs: Linux web servers are case-sensitive. Spaces cause broken %20 links.
snake_case user_profile.php, total_price Backend scripts, database tables, PHP variables Use underscores to separate words.
camelCase handleUserSubmit(), navToggleBtn JavaScript variables, functions, and methods First letter lowercase, subsequent word beginnings capitalized.
PascalCase UserProfileCard, NavigationMenu JavaScript classes, React/Vue components Capitalize the first letter of each word.
lowercase index.html, style.css All web file names and standard HTML tags Never use capital letters in web assets to avoid 404 errors on Apache/Linux servers.
🔗 Relative vs. Absolute File Path Referencing

Correct path referencing is critical to ensure links and assets load both locally and on live production servers:

  • Same directory: <img src="hero.jpg"> or <img src="./hero.jpg">
  • Subdirectory: <link rel="stylesheet" href="css/styles.css">
  • Parent directory: <script src="../js/main.js"></script> (moves up one level)
  • Root-relative absolute path: <img src="/images/logo.png"> (resolves from web server document root)
  • Fully qualified URL: <a href="https://example.com"> (external references)

🔄 Client-Server Architecture & Network Types

The Client-Server model is the foundational architecture of the Internet:

  • Clients: End-user devices or software applications (desktop browsers, smartphones, tablets) that formulate and send requests to servers.
  • Servers: High-performance daemon software running on computers that listen for incoming requests, process business logic, query databases, and return responses (HTML, CSS, JSON, media) over the TCP/IP protocol suite.
  • Request-Response Model: The client initiates an HTTP/HTTPS request specifying a resource (URI). The server processes the request and responds with a status code and payload.
Network Type Definition Subdivisions & Technology Access Scope
Intranet A private, isolated network accessible only to authenticated staff within a single organization (enterprise, school, government). Protected behind strict firewalls. Local Area Network (LAN): High-speed connections across a single room, building, or campus. Internal authorized personnel only
Extranet An authorized extension of an intranet allowing trusted external stakeholders (suppliers, vendors, business partners, customers) restricted access to specific internal resources. Virtual Private Network (VPN): Encrypted tunnels traversing the public internet with cryptographic authentication. Organization staff plus approved external partners
Internet The globally interconnected network of millions of public computers and routers communicating via the TCP/IP protocol suite. Comprises public data centers, tier-1 ISPs, IXPs, and interconnected public subnets. Open to the worldwide public

📦 Complete Step-by-Step XAMPP Setup & Testing Guide

A local web server simulates a live production server directly on your development computer, allowing you to test server-side scripts (PHP), databases (MySQL), and relative URLs without requiring an internet connection.

WAMP: Windows specific stack.
MAMP: macOS optimized stack.
LAMP: Linux native server stack (Ubuntu/CentOS).
Live Server: VS Code extension ideal for real-time static HTML/CSS/JS development.

Practical Procedure (from CBLM)

How to Install, Configure, and Test XAMPP on Windows

  1. Download: Visit the official Apache Friends website (https://www.apachefriends.org) and download the latest XAMPP for Windows installer.
  2. Run Installer: Double-click the downloaded xampp-windows-x64-installer.exe. If prompted by Windows User Account Control (UAC), click Yes.
  3. Component Selection: Select the required modules: Apache (Web Server), MySQL (Database), and phpMyAdmin.
  4. Installation Directory: Default installation destination is C:\xampp. Complete the wizard and click Finish.
  5. Launch Control Panel: Open the XAMPP Control Panel from the Windows Start Menu.
  6. Start Services:
    • Click Start next to Apache (runs on standard Port 80 and SSL Port 443).
    • Click Start next to MySQL (runs on Port 3306).
    • When the module labels turn green, the servers are operational.
  7. Verify Default Host: Open your web browser and navigate to http://localhost or http://127.0.0.1. The XAMPP dashboard page will appear.
  8. Create a Test PHP Page:
    • Navigate to the document root directory: C:\xampp\htdocs\.
    • Create a new folder named Test.
    • Inside C:\xampp\htdocs\Test\, open a text editor and create a file named test.php.
    • Type the following verification script and save:
PHP (C:\xampp\htdocs\Test\test.php)
<!doctype html>
<html>
<head>
  <title>Test Page</title>
</head>
<body>
  <p>XAMPP Server runs successfully</p>
</body>
</html>

Verification Result

In your web browser, navigate to http://localhost/Test/test.php. If the page displays "XAMPP Server runs successfully", your local web server is correctly installed, configured, and ready for web application development.

The 8 Steps of Live Website Deployment

  1. Domain Registration: Purchase an address (e.g. mybrand.com.bd) via an ICANN/BTCL accredited registrar.
  2. DNS Configuration: Point domain Nameservers to your host, or configure the A Record with the server's public IPv4 address.
  3. Choose Hosting Architecture: Shared cPanel hosting (entry-level), Virtual Private Server / VPS (intermediate), or Cloud PaaS (Vercel, Netlify, AWS).
  4. Server Configuration: Set default document root (typically /public_html or /var/www/html), configure URL rewrites (.htaccess for Apache or nginx.conf for Nginx).
  5. File Upload via FTP/SFTP: Connect via FileZilla or Cyberduck and upload all HTML, CSS, JS, and asset folders.
  6. Database Setup: If dynamic, import MySQL .sql dumps using phpMyAdmin and update database connection credentials.
  7. Security Configuration: Install an SSL/TLS Certificate (free via Let's Encrypt), enforce HTTPS redirection, set Linux file permissions (644 for files, 755 for directories).
  8. Live Testing: Validate all URLs, responsive viewports, and test page speed across desktop and mobile devices.

Configuration Procedure (from CBLM)

How to Connect to a Live Server via FileZilla Site Manager

  1. Locate Credentials: Log into your web hosting control panel (cPanel). Under the Files section, click FTP Accounts, scroll down and click Configure FTP Client to retrieve Hostname, Username, Port, and Password.
  2. Open Site Manager: In FileZilla, click File > Site Manager (or press Ctrl+S). Click New Site and name your connection (e.g. My Live Portfolio).
  3. Enter Connection Details:
    • Protocol: Select FTP - File Transfer Protocol or SFTP - SSH File Transfer Protocol (recommended).
    • Host: Enter your domain or FTP server hostname (e.g. ftp.example.com or server IP).
    • Port: Enter 21 for standard FTP / FTPS, or 22 for SFTP.
    • Encryption: Choose Use explicit FTP over TLS if available for secure transfer.
    • Logon Type: Select Normal (never Anonymous for web hosting).
    • User: Enter your FTP username (e.g. user@example.com or cPanel user).
    • Password: Enter your secure FTP password.
  4. Connect: Click Connect. If prompted with a certificate verification dialog, inspect the SSL certificate and check Always trust certificate in future sessions.
  5. The Dual-Pane Interface:
    • Left Pane (Local Site): Displays your personal computer's local folders and project files.
    • Right Pane (Remote Site): Displays the remote web server directory structure (navigate into public_html).
  6. Uploading Files: Select files/folders in the left pane, right-click and choose Upload (or drag and drop into the right pane). Files will queue and transfer with progress indicators shown in the bottom transfer queue panel.
  7. Downloading Files: Highlight remote files in the right pane, right-click and choose Download.

🎛️ cPanel File Manager & Server Security Settings

When third-party FTP software is unavailable, web hosting control panels provide the cPanel File Manager directly inside the browser:

  • Browser-Based File Operations: Upload, move, copy, rename, delete, and view file permissions directly in public_html.
  • Built-in Code Editor: Make quick hotfixes to HTML, CSS, or PHP files without downloading and re-uploading.
  • ZIP Compression & Extraction: Compress entire site directories into a single .zip file for fast bulk upload, then use Extract inside cPanel to unpack instantly.
  • Linux File Permissions (chmod):
    • Files (HTML, CSS, JS, Images): Must be set to 644 (Owner: Read/Write; Group: Read; World: Read).
    • Directories / Folders: Must be set to 755 (Owner: Read/Write/Execute; Group: Read/Execute; World: Read/Execute).
    • Security Warning: Never set production files or folders to 777 (unrestricted write access).

🗄️ Data Layer Architecture & Storage Solutions

In modern web systems, the Data Layer (Data Tier / Access Layer) acts as an intermediary separating the user interface presentation layer from physical persistent storage. It abstracts underlying databases, manages data retrieval, enforces validation rules, and ensures security and caching.

Storage Mechanism Format / Engine Characteristics & Best Use Cases
Static Data Files JSON, CSV, Excel (.xlsx), PDF Plain text tabular or serialized datasets. Extremely fast for read-only catalogues, reports, data imports/exports.
Cloud Spreadsheets Google Sheets API Collaborative online spreadsheets accessible via Google Sheets REST API. Great for simple CMS backends, event registrations, and low-code integrations.
Relational Databases (RDBMS) MySQL, MariaDB, PostgreSQL Structured tables with defined schemas, relationships (foreign keys), and SQL queries. Managed visually via phpMyAdmin. Standard for e-commerce, user accounts, and financial transactions.
NoSQL Databases MongoDB, Redis, Apache Cassandra Schema-less JSON-like documents (MongoDB), high-speed key-value caches (Redis), or distributed wide-column stores (Cassandra). Handles unstructured, rapidly evolving, high-velocity datasets.

🔌 Web APIs: REST vs. SOAP vs. GraphQL

A Web API (Application Programming Interface) defines the communication protocols and data exchange formats between independent software applications across the internet:

API Type Protocol / Standard Data Payload Key Characteristics
RESTful API (Representational State Transfer) HTTP / HTTPS JSON, XML Stateless, uses standard HTTP methods (GET, POST, PUT, DELETE), resource URIs, and universal client compatibility. The industry standard for web development.
SOAP API (Simple Object Access Protocol) HTTP, SMTP, TCP Strict XML only Strict contract defined by WSDL files. Heavy overhead but features built-in ACID compliance and enterprise-grade WS-Security. Common in legacy banking systems.
GraphQL API HTTP POST JSON Client queries exactly the fields it needs in a single request. Eliminates over-fetching (too much data) and under-fetching (too many network requests). Developed by Meta.
HTTP Method CRUD Action Function Example Endpoint
GET Read Retrieve a resource or collection of resources from the server GET /api/v1/products
POST Create Send new data to the server to create a new resource POST /api/v1/products
PUT / PATCH Update Update or replace an existing resource on the server PUT /api/v1/products/42
DELETE Delete Remove a specified resource from the server DELETE /api/v1/products/42

Frontend-Backend Data Binding Example

JavaScript (Async Data Layer Fetch)
// 1. Client data layer request using async/await
async function loadCatalog() {
  const container = document.getElementById('product-grid');
  container.innerHTML = '<p>Loading catalog...</p>';

  try {
    const response = await fetch('https://api.example.com/v1/products', {
      method: 'GET',
      headers: { 'Accept': 'application/json' }
    });

    if (!response.ok) {
      throw new Error(`HTTP Error: ${response.status}`);
    }

    const products = await response.json();
    
    // 2. Transform and render data into UI
    container.innerHTML = products.map(p => `
      <div class="product-card">
        <h4>${p.title}</h4>
        <p class="price">৳${p.price}</p>
      </div>
    `).join('');

  } catch (error) {
    console.error('Data layer failure:', error);
    container.innerHTML = '<p class="error">Unable to load catalog.</p>';
  }
}

document.addEventListener('DOMContentLoaded', loadCatalog);

⌨️ 16 Essential Git Commands (CS V2 Range of Variables)

The CS V2 Range of Variables (Variable 12) explicitly mandates knowledge and demonstration of 16 specific Git commands:

# Command Action / Purpose Practical Command Syntax
12.1 git init Initializes a new, empty Git repository inside the current project root. git init
12.2 git clone Downloads a complete copy of an existing remote repository to local disk. git clone https://github.com/user/project.git
12.3 git add Stages modified or newly created files for inclusion in the next commit. git add . (all files) or git add index.html
12.4 git commit Permanently records staged snapshots into project history with a message. git commit -m "Add responsive navigation"

12.8 git branch Lists, creates, or deletes branches in the local repository. git branch feature-gallery
12.9 git pull Fetches changes from a remote repository and immediately merges them into the active branch. git pull origin main
12.10 git merge Combines the commit history of a specified branch into the active branch. git merge feature-gallery
12.11 git checkout / git switch Switches branches or restores working tree files. git checkout -b feature-gallery
12.12 git reset Unstages files or rolls back the repository commit pointer to a specified state. git reset HEAD~1
12.13 git rm Removes files from the working directory and stops tracking them in Git. git rm obsolete-template.html
12.14 git mv Renames or moves tracked files/directories while maintaining commit history. git mv old-style.css css/styles.css
12.15 git tag Creates annotated milestone tags pointing to specific release commits. git tag -a v1.0.0 -m "Initial release"
12.16 git help Opens official documentation and manual pages for any Git command. git help commit

🎯 NSDA Exam Preparation: Question Bank & MCQs

High-frequency exam questions (Basic to Advanced) reflecting both modern CS V2 criteria and CBLM core competencies.

Part 1: Multiple Choice Questions (MCQs)

Basic
1. What is the default root document directory for web pages hosted on a standard local XAMPP installation on Windows?
A C:\xampp\www\
B C:\xampp\htdocs\
C C:\Program Files\Apache\web\
D C:\Users\Public\Documents\
View Correct Answer & Explanation
Correct Answer: B — C:\xampp\htdocs\ is Apache's primary DocumentRoot. Files placed inside are accessed in your browser via http://localhost/filename.html.
Intermediate
2. Which standard network port is designated for unencrypted FTP file transfers, and which port is used for secure SFTP (SSH File Transfer Protocol)?
A FTP: Port 80; SFTP: Port 443
B FTP: Port 21; SFTP: Port 22
C FTP: Port 25; SFTP: Port 110
D FTP: Port 3306; SFTP: Port 8080
View Correct Answer & Explanation
Correct Answer: B — Standard FTP operates on Port 21. SFTP operates over an encrypted SSH connection on Port 22.
Advanced
3. When deploying a web application to an Apache/Linux production web server, what are the recommended secure file permissions (chmod) for web assets (HTML/CSS/JS) and directories?
A Files: 777; Directories: 777
B Files: 644; Directories: 755
C Files: 755; Directories: 644
D Files: 400; Directories: 500
View Correct Answer & Explanation
Correct Answer: B — chmod 644 allows read/write for owner and read-only for others; chmod 755 allows directory traversing and reading without granting malicious write access. Setting 777 is a dangerous security hazard.

Part 2: Written & Oral Questions with Detailed Answers

Basic
Q1: List the five standard Git states and describe the step-by-step procedure to stage, commit, and push new code to GitHub.

The Five Git States: Untracked, Working Directory (Modified), Staging Area (Index), Local Repository (Committed), and Remote Repository.

Deployment Procedure:

  1. Check status: git status (inspect changed files).
  2. Stage files: git add . (moves changes to Staging Area).
  3. Commit: git commit -m "feat: complete responsive header" (creates an immutable snapshot).
  4. Push: git push origin main (synchronizes commits with remote GitHub repository).
Intermediate
Q2: Compare the difference between RESTful APIs and GraphQL APIs in modern data layer architectures.

RESTful API: Architectural style organized around resource endpoints (URIs). Uses standard HTTP methods (GET, POST, PUT, DELETE). Responses have fixed data structures, which can lead to over-fetching (receiving unnecessary fields) or under-fetching (requiring multiple round-trip requests to gather related data).

GraphQL API: Query language where clients specify the exact shape and fields of data required in a single request. Operates via a single HTTP POST endpoint, reducing network payloads and mobile bandwidth consumption.

Advanced
Q3: You are deploying a client website that requires both a database connection and custom routing. How do you configure DNS, Web Server settings, and SSL encryption for secure live access?
  1. DNS Configuration: Create an A Record pointing @ and www to the web server's static public IPv4 address. Wait for TTL propagation.
  2. Server Virtual Host / Directory: Point server virtual host document root to /public_html. Configure URL rewrite rules (via .htaccess for Apache mod_rewrite or try_files block in Nginx) to route traffic through index.html.
  3. Database Configuration: In cPanel/phpMyAdmin, create a dedicated database and database user with strong password; assign GRANT ALL PRIVILEGES on that specific database only.
  4. SSL/TLS Certificate: Install a Let's Encrypt SSL certificate via cPanel AutoSSL or Certbot. Enforce 301 permanent redirect from HTTP to HTTPS in server configuration.

Self-Check 1: Client-Server Architecture (Questions & Answers)▼

Q1: What is the purpose of setting up a Client-Server architecture?
Answer: To establish a computing model where multiple client devices (computers, smartphones) communicate with a central server to access shared resources, services, and data efficiently.

Q2: What are the main components involved in a Client-Server setup?
Answer: 1. Clients (request resources), 2. Server (manages and serves resources), 3. Network (communication medium connecting clients and servers).

Q3: What are the advantages of Client-Server architecture?
Answer: Centralized control, easier backup and maintenance, improved security, scalability, and concurrent multi-user request handling.

Q4: What types of services can be provided in a Client-Server setup?
Answer: Web hosting, file sharing, database management, email services, and application hosting.

Q5: How does communication occur between clients and the server?
Answer: Through standard network protocols (TCP/IP, HTTP/HTTPS) using a request-response cycle.

Q1: What is the purpose of installing FTP clients?
Answer: To enable users to connect to and transfer files between their local computer and a remote web hosting server over the File Transfer Protocol.

Q2: What is an FTP client?
Answer: A software application that provides a graphical user interface (GUI) to perform file uploads, downloads, deletions, and directory management on remote servers.

Q3: How does an FTP client work?
Answer: It connects to an FTP daemon on port 21 (or SFTP on port 22), authenticates user credentials, displays the remote file system, and streams files in queues.
