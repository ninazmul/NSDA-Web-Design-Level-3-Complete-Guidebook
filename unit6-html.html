Unit 6: Work with HTML

Unit Code: OU-ICT-WD-03-L3-V2
This unit covers using HTML (HyperText Markup Language) to create structured, accessible, and standards-compliant web content, including semantic layouts, multimedia, forms, and W3C validation.

📋 Overview

HTML is the foundation of every web page. It defines the structure and content of your website — text, images, links, forms, and multimedia. This unit covers everything from basic document structure to advanced accessibility features.

🏗️ Element 1: Create HTML Structure

📄 HTML5 Boilerplate

HTML
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <meta name="description" content="A brief description of the page">
  <title>Page Title</title>
  <link rel="stylesheet" href="css/styles.css">
</head>
<body>
  <!-- Your content goes here -->

  <script src="js/main.js"></script>
</body>
</html>

📋 Element 3: Create and Manage Forms

HTML
<form action="/submit" method="POST" id="contact-form">
  <fieldset>
    <legend>Contact Information</legend>

    <label for="name">Full Name:</label>
    <input type="text" id="name" name="name"
      required placeholder="Enter your name">

    <label for="email">Email:</label>
    <input type="email" id="email" name="email"
      required placeholder="you@example.com">

    <label for="phone">Phone:</label>
    <input type="tel" id="phone" name="phone"
      placeholder="+880-1234567890">
  </fieldset>

  <fieldset>
    <legend>Message</legend>

    <label for="subject">Subject:</label>
    <select id="subject" name="subject">
      <option value="">Select a topic</option>
      <option value="general">General Inquiry</option>
      <option value="project">Project Request</option>
    </select>

    <label for="message">Message:</label>
    <textarea id="message" name="message" rows="5"
      required placeholder="Type your message..."></textarea>
  </fieldset>

  <button type="submit">Send Message</button>
  <button type="reset">Clear Form</button>
</form>

♿ Element 4: Accessibility & Standards Compliance

🏷️ ARIA Roles and Attributes

HTML
<!-- Navigation with ARIA -->
<nav role="navigation" aria-label="Main Navigation">
  <ul>
    <li><a href="/">Home</a></li>
    <li><a href="/about">About</a></li>
  </ul>
</nav>

<!-- Image with alt text -->
<img src="logo.png" alt="Company Name Logo">

<!-- Decorative image (empty alt) -->
<img src="decoration.png" alt="" role="presentation">

<!-- Skip navigation link for keyboard users -->
<a href="#main-content" class="skip-link">Skip to main content</a>

<!-- Tab index for keyboard navigation -->
<div tabindex="0" role="button" aria-label="Toggle menu">
  ☰ Menu
</div>
💡 Accessibility Checklist

✅ All images have descriptive alt attributes

✅ All form inputs have associated <label> elements

✅ Page has a logical heading hierarchy (H1 → H2 → H3)

✅ Color contrast meets WCAG 4.5:1 ratio

✅ All interactive elements are keyboard-accessible

✅ ARIA roles are used for non-semantic interactive elements

✅ HTML validated via W3C Validator (validator.w3.org)

HTML Validation Tools

  • W3C Validator: validator.w3.org — Official HTML validation
  • Browser DevTools: Elements panel shows errors and warnings

🎯 NSDA Exam Preparation: Question Bank & MCQs

Master these essential HTML5 written exam and practical oral questioning items (Basic to Advanced) for NSDA Level 3 certification.

Part 1: Multiple Choice Questions (MCQs)

Basic
1. Which HTML5 element should be used to enclose self-contained content that could theoretically be distributed or republished independently (such as a blog post or news story)?
A <div>
B <section>
C <article>
D <aside>
View Correct Answer & Explanation
Correct Answer: C — <article> represents independent, self-contained syndicateable content, whereas <section> groups thematically related page content with a heading.
Intermediate
2. How should an accessible form input field be strictly paired with its descriptive label to ensure assistive screen readers identify the field upon focus?
A Match the label's for attribute with the input's id attribute
B Match the label's name attribute with the input's class attribute
C Place the label after the input with a placeholder
D Wrap both in a <span> tag without attributes
View Correct Answer & Explanation
Correct Answer: A — <label for="user-email">Email</label> strictly links with <input id="user-email" ...>. Clicking the label also moves input focus directly to the control.
Advanced
3. When implementing modern responsive images with art direction (serving different aspect ratios or cropped images on mobile vs. desktop), which HTML5 element should be utilized?
A <canvas> with JavaScript resize listeners
B <picture> containing multiple <source> elements with media queries and a fallback <img>
C Multiple <img> tags hidden with CSS display: none
D An embedded <iframe> pointing to image URLs
View Correct Answer & Explanation
Correct Answer: B — The <picture> element enables art direction and WebP/AVIF format negotiation before downloading, preventing wasted mobile data.

Part 2: Written & Oral Questions with Detailed Answers

Basic
Q1: What is the purpose of the <!DOCTYPE html> declaration and the viewport meta tag in an HTML5 document?

<!DOCTYPE html>: Instructs the web browser's rendering engine to parse and render the document in full standard compliance mode rather than legacy "quirks mode".

Viewport Meta Tag: <meta name="viewport" content="width=device-width, initial-scale=1.0"> ensures that mobile devices render the web page at a 1:1 scale matching the device screen width, preventing mobile browsers from shrinking pages into an unreadable desktop view.

Intermediate
Q2: Describe the structural hierarchy of semantic HTML tables and explain when to use colspan and rowspan.

Semantic Table Hierarchy:

  • <caption>: Accessible table title.
  • <thead>: Header row container containing column labels formatted with <th scope="col">.
  • <tbody>: Body container holding primary data rows (<tr>) and cells (<td>).
  • <tfoot>: Summary or totals row (<tfoot>).

Cell Merging: colspan="N" expands a single cell across N columns horizontally; rowspan="N" expands a cell across N rows vertically.

Advanced
Q3: What are ARIA roles and landmarks, and what are the best practices for building an accessible modal dialog or navigation menu?

WAI-ARIA (Accessible Rich Internet Applications): Attributes extending HTML to communicate widget semantics, states, and properties to assistive screen readers.

  • Rule 1 (First Rule of ARIA): Use native semantic HTML elements first (e.g. <button>, <nav>). Only use ARIA when native tags cannot convey the state.
  • Modal Dialog Pattern: Apply role="dialog" and aria-modal="true", link title with aria-labelledby="modal-title", trap keyboard focus (Tab key) inside the modal, and close on Escape key.
  • Accessible Toggles: Use aria-expanded="true/false" and aria-controls="nav-menu" on mobile hamburger buttons so screen readers announce menu open/close states.
