Unit 6: Work with HTML

Unit Code: OU-ICT-WD-03-L3-V2
This unit covers using HTML (HyperText Markup Language) to create structured, accessible, and standards-compliant web content, including semantic layouts, multimedia, forms, and W3C validation.

📋 Overview

HTML is the foundation of every web page. It defines the structure and content of your website — text, images, links, forms, and multimedia. This unit covers everything from basic document structure to advanced accessibility features.

🏗️ Element 1: Create HTML Structure

📄 HTML5 Boilerplate

HTML
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">

  <link rel="stylesheet" href="css/styles.css">
</head>

  <!-- Your content goes here -->

  <script src="js/main.js"></script>
</body>
</html>

Part 2: Written & Oral Questions with Detailed Answers

Basic
Q1: What is the purpose of the '<!DOCTYPE html>' declaration and the viewport meta tag in an HTML5 document?

<!DOCTYPE html>: Instructs the web browser's rendering engine to parse and render the document in full standard compliance mode rather than legacy 'quirks mode'. Without it, browsers may render CSS margins, box sizing, and fonts unpredictably.

Viewport Meta Tag: <meta name="viewport" content="width=device-width, initial-scale=1.0"> ensures that mobile devices render the web page at a 1:1 scale matching the device screen width, preventing mobile browsers from shrinking pages into an unreadable desktop view.

Basic
Q2: Explain the difference between block-level elements and inline elements in standard HTML.

Block-Level Elements (e.g., <div>, <p>, <h1>-<h6>, <section>, <ul>):

  • Always start on a new line.
  • Stretch horizontally to occupy the full available width of their parent container.
  • Respect top, bottom, left, and right margins and padding.

Inline Elements (e.g., <span>, <a>, <strong>, <em>, <img>):

  • Flow inline with text without breaking onto a new line.
  • Only take up as much width as their content demands.
  • Do not respect top and bottom vertical margins or heights (unless converted via CSS display: inline-block or block).
Basic
Q3: Why is it important to use only a single '<h1>' heading on a web page, and what heading hierarchy rules apply?

Single <h1> Rule: The <h1> communicates the primary topic and purpose of the entire document to search engines and screen readers. Having multiple <h1> tags dilutes SEO keyword weight and confuses screen reader users who navigate pages by skipping through headings.

Heading Hierarchy Rules: Headings must follow a logical nested numerical sequence (<h1> → <h2> → <h3>). You should never skip levels (e.g., jumping from <h2> directly to <h4>) purely for visual styling purposes.

Basic
Q4: What is the difference between relative and absolute URLs when linking pages and assets?

Absolute URLs: Include the entire protocol, domain name, and complete path (e.g., https://example.com/images/logo.png). Used when linking to external resources or third-party APIs.

Relative URLs: Point to a file relative to the current document's location (e.g., ./about.html, ../css/styles.css, or root-relative /images/hero.jpg). Relative URLs are portable, allowing web projects to function identically in local testing (localhost) and live production domains without hardcoded URLs breaking.

Intermediate
Q5: Describe the structural hierarchy of semantic HTML tables and explain when to use 'colspan' and 'rowspan'.

Semantic Table Hierarchy:

  • <caption>: Accessible table title describing the dataset.
  • <thead>: Header row container containing column labels formatted with <th scope="col">.
  • <tbody>: Body container holding primary data rows (<tr>) and cells (<td>).
  • <tfoot>: Summary or totals row (e.g., total price, averages).

Cell Merging: colspan="N" expands a single cell across N columns horizontally; rowspan="N" expands a cell across N rows vertically.

Intermediate
Q6: Compare the semantic differences and proper use cases for '<section>', '<article>', and '<div>'.
  • <article>: Represents a complete, self-contained piece of content that could stand alone and be syndicated independently (e.g., blog post, newspaper article, forum thread, product card).
  • <section>: Represents a thematic grouping of content, typically with its own heading (e.g., 'About Us', 'Features', 'Contact Form'). It should not be used as a generic styling wrapper.
  • <div>: Has zero semantic meaning. It is purely a stylistic container used to group elements for CSS layouts, flexbox wrappers, or JavaScript hooks when no semantic tag fits.
Intermediate
Q7: How do you construct an accessible, client-side validated HTML5 form without writing JavaScript?

Use native HTML5 form attributes and semantic controls:

<form action="/submit" method="POST" novalidate="false">
  <fieldset>
    <legend>Personal Details</legend>
    
    <label for="fullname">Full Name (Required):</label>
    <input type="text" id="fullname" name="fullname" required minlength="3" autocomplete="name">
    
    <label for="email">Work Email:</label>
    <input type="email" id="email" name="email" required autocomplete="email">
    
    <label for="phone">Bangladesh Phone:</label>
    <input type="tel" id="phone" name="phone" pattern="^(\+8801|01)[3-9][0-9]{8}$" placeholder="017XXXXXXXX" required>
    
    <button type="submit">Submit Application</button>
  </fieldset>
</form>

Attributes like required, type="email", and pattern trigger native browser validation tooltips and block invalid submission automatically.

Intermediate
Q8: Explain the mechanics of the '<picture>' element for Art Direction and Next-Gen format delivery.

The <picture> element evaluates <source> elements from top to bottom and renders the first matching condition:

<picture>
  <!-- 1. Next-gen AVIF for desktop -->
  <source media="(min-width: 1024px)" srcset="hero-large.avif" type="image/avif">
  <!-- 2. Next-gen WebP for mobile -->
  <source media="(max-width: 768px)" srcset="hero-cropped-mobile.webp" type="image/webp">
  <!-- 3. Universal JPG fallback -->
  <img src="hero-fallback.jpg" alt="Developer team collaborating" width="1200" height="600" loading="lazy">
</picture>

This delivers two huge benefits: Format Optimization (serving modern compressed AVIF/WebP) and Art Direction (serving a vertically cropped image for mobile portrait screens).

Advanced
Q9: What are ARIA roles and landmarks, and what are the best practices for building an accessible modal dialog or navigation menu?

WAI-ARIA (Accessible Rich Internet Applications): Attributes extending HTML to communicate widget semantics, states, and properties to assistive screen readers.

  • Rule 1 (First Rule of ARIA): Use native semantic HTML elements first (e.g. <button>, <nav>). Only use ARIA when native tags cannot convey the state.
  • Modal Dialog Pattern: Apply role="dialog" and aria-modal="true", link title with aria-labelledby="modal-title", trap keyboard focus (Tab key) inside the modal, and close on Escape key.
  • Accessible Toggles: Use aria-expanded="true/false" and aria-controls="nav-menu" on mobile hamburger buttons so screen readers announce menu open/close states.
Advanced
Q10: How do you optimize an HTML document to pass W3C Markup Validation and achieve high Google Core Web Vitals (LCP, CLS, INP)?

W3C Markup Validation Checklist:

  1. Verify valid <!DOCTYPE html> and <html lang="en">.
  2. Ensure all open tags are cleanly closed in proper nesting order without overlapping.
  3. Ensure every <img> has an alt attribute.
  4. Ensure all id attributes are strictly unique within the document.

Core Web Vitals Optimization:

  • Prevent CLS (Cumulative Layout Shift): Always assign explicit width and height or CSS aspect-ratio on all images and video containers so the browser pre-calculates reserved space.
  • Improve LCP (Largest Contentful Paint): Preload hero images using <link rel="preload" as="image" href="hero.webp"> and avoid lazy-loading above-the-fold hero banners.
  • Improve INP (Interaction to Next Paint): Defer non-critical scripts with <script defer src="app.js"> to prevent parser blocking on the main thread.
Advanced
Q11: Explain Open Graph meta tags and JSON-LD Structured Data for rich search engine snippets and social sharing.

Open Graph (OG) Meta Tags: Standardized protocol used by Facebook, LinkedIn, Twitter/X, and messaging apps to generate rich preview cards when your link is shared:

<meta property="og:title" content="NSDA Web Design Level 3 Complete Guide">

Q12: How do you ensure full keyboard accessibility (Tab, Enter, Space, Escape) across complex custom HTML interactive components?

To ensure non-mouse users can navigate an interactive website:

  1. Use Native Focusable Elements: Build buttons with <button> and links with <a href>. They automatically accept keyboard focus and trigger on Enter and Space keys.
  2. Never Remove Outline Without a Fallback: Never write outline: none; without supplying an obvious, high-contrast :focus-visible indicator ring.
  3. Manage Custom Focus with tabindex: For custom widgets, use tabindex="0" to place in sequential tab order, and tabindex="-1" for sub-elements focused programmatically via JavaScript.
  4. Implement Focus Trapping in Modals: When a modal dialog opens, listen for keydown events. If Tab is pressed on the last interactive child, loop focus back to the first child. When Escape is pressed, close the modal and return focus back to the triggering button.
