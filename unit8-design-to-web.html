Unit 8: Perform Design to Web

Unit Code: OU-ICT-WD-05-L3-V2
This unit covers converting visual design files (PSD, Figma, XD) into responsive, functional web pages using HTML, CSS, and JavaScript. It involves interpreting layout specifications, slicing assets, and building code structures that reflect the design accurately.

📋 Overview

Design-to-Web (also called "PSD to HTML" or "Design to Code") is the critical process of transforming visual mockups created in design tools into fully functional, responsive web pages. This requires careful attention to pixel-perfect accuracy, performance optimization, and cross-browser compatibility.

💡 The Design-to-Code Pipeline

Designer creates mockup → Developer inspects design → Extract assets → Write HTML structure → Apply CSS styling → Add JavaScript interactivity → Test & optimize → Deliver

🔍 Element 1: Inspect Design Files

PC 1.1 – 1.5

What to Look for in Design Files

When opening a design file, systematically inspect and note:

  • Layout grids: Column count, gutter width, margins — determines your CSS grid structure
  • Typography: Font families, sizes, weights, line heights, letter spacing for every text element
  • Design tokens: Colors, spacing values, border radius, shadows — build your CSS variables from these
  • Color palettes: Primary, secondary, accent colors with their exact HEX/RGB values
  • Spacing and margins: Padding, margins, gaps between elements (in pixels or rems)
  • Responsiveness: Check if the design has mobile, tablet, and desktop variants
  • Asset types: Identify images, icons, illustrations, and their required export formats

🎨 Working with Figma

Figma Inspection Workflow

Figma is the most popular design tool for web design due to its collaborative features and browser accessibility.

Key Figma Features for Developers:

  • Inspect Panel: Click any element to see CSS properties (width, height, colors, fonts, spacing)
  • Dev Mode: Toggle to Dev Mode for auto-generated CSS code snippets
  • Export Settings: Select layers and choose export format (PNG, SVG, JPG, WebP)
  • Design Tokens: Copy colors, fonts, and spacing values directly
  • Auto Layout: Figma's auto layout translates directly to Flexbox in CSS
  • Components: Identify reusable components that map to HTML/CSS components
🎯 Extracting CSS from Figma

Step 1: Click on the element in Figma

Step 2: Check the right panel "Inspect" tab

Step 3: Copy CSS values — font-family, font-size, color, width, padding, border-radius

Step 4: Convert pixel values to rem (divide by 16): 24px → 1.5rem

Step 5: Note any hover states, active states, or animations specified

✨ Working with Adobe XD

Adobe XD Workflow

  • Share for Development: Use "Share > Development" to create inspection links
  • Design Specs: View exact measurements, colors, and fonts
  • Asset Export: Select elements → Mark for Export → Choose format and scale
  • Prototype Preview: Review interactions and transitions that need to be coded
  • Character Styles: Check the character styles panel for typography specs

🖌️ Working with Photoshop (PSD)

Photoshop Workflow

  • Layer Organization: Review layer names and groups for component structure
  • Slice Tool: Use the slice tool to cut images for web export
  • Save for Web: File → Export → Save for Web (Legacy) for optimized images
  • Measurement: Use the ruler tool and info panel for exact dimensions
  • Extract Assets: Right-click layer → Quick Export as PNG/SVG
  • Color Picker: Use the eyedropper to capture exact color codes

📦 Element 2: Export and Optimize Design Assets

PC 2.1 – 2.5

Asset Export Process

  1. Create folder structure — images/, icons/, fonts/ following best practices
  2. Identify all exportable assets — Images, icons, illustrations, logos
  3. Export at correct sizes — 1x, 2x (Retina), and 3x for responsive images
  4. Apply naming conventions — hero-banner.jpg, icon-search.svg, logo-dark.png
  5. Optimize file sizes — Compress without visible quality loss

💡 Image Optimization Best Practices

✅ Use SVG for icons and logos (scales infinitely, tiny file size)

✅ Use WebP for photographs with JPEG fallback

✅ Compress images using tools like TinyPNG, Squoosh, or ImageOptim

✅ Always specify width and height attributes to prevent layout shift

✅ Use loading="lazy" for below-the-fold images

✅ Serve responsive images with <picture> element or srcset

Responsive Image Example

HTML
<!-- Responsive image with srcset -->
<img
  src="images/hero-800.jpg"
  srcset="images/hero-400.jpg 400w,
         images/hero-800.jpg 800w,
         images/hero-1200.jpg 1200w"
  sizes="(max-width: 600px) 400px,
        (max-width: 1000px) 800px,
        1200px"
  alt="Hero banner image"
  loading="lazy"
  width="1200"
  height="600">

<!-- Picture element for format fallback -->
<picture>
  <source srcset="images/photo.avif" type="image/avif">
  <source srcset="images/photo.webp" type="image/webp">
  <img src="images/photo.jpg" alt="Photo description">
</picture>

🔨 Element 3: Build Web Page Based on Design

🔄 Design-to-Code Workflow

Step-by-Step Conversion Process

Step 1 — Analyze the Visual Hierarchy:

  • Identify the header, main content, sidebar, and footer sections
  • Map design sections to semantic HTML elements (<header>, <main>, <section>, <footer>)

Step 2 — Write the HTML Structure:

  • Build the skeleton with semantic elements following the design layout
  • Add content text, images, and links as specified in the design

Step 3 — Apply CSS Styling:

  • Set up CSS variables from design tokens (colors, fonts, spacing)
  • Replicate exact spacing, colors, fonts, and dimensions from the design
  • Use Flexbox or Grid for layout structure

Step 4 — Integrate Web Fonts and Icons:

  • Link Google Fonts or custom web fonts matching the design
  • Use icon libraries (Font Awesome, Material Icons) or custom SVG icons

Step 5 — Add Interactive Components:

  • Build dropdowns, modals, tabs, carousels using CSS and basic JavaScript
  • Add hover states, transitions, and animations from the design specs

Step 6 — Implement Responsive Design:

  • Apply media queries for mobile, tablet, and desktop breakpoints
  • Use Flexbox/Grid for flexible layouts
  • Test on multiple screen sizes

Example: Converting a Design Token to CSS Variables

CSS
/* Design tokens extracted from Figma */
:root {
  /* Colors from design */
  --color-primary: #2563eb;
  --color-secondary: #7c3aed;
  --color-text: #1e293b;
  --color-text-muted: #64748b;
  --color-bg: #ffffff;

  /* Typography from design */
  --font-heading: 'Inter', sans-serif;
  --font-body: 'Inter', sans-serif;

  /* Spacing from design (8px grid system) */
  --space-xs: 0.25rem;  /* 4px */
  --space-sm: 0.5rem;   /* 8px */
  --space-md: 1rem;     /* 16px */
  --space-lg: 1.5rem;   /* 24px */
  --space-xl: 2rem;     /* 32px */

  /* Border radius from design */
  --radius-sm: 4px;
  --radius-md: 8px;
  --radius-lg: 16px;
  --radius-full: 9999px;
}

Part 2: Written & Oral Questions with Detailed Answers

Basic
Q1: Explain the sequential design-to-code workflow when converting a visual Figma/PSD mockup into a responsive website.
  1. Design Audit: Inspect the layout grid (columns, gutter), extract brand color codes (HEX/HSL), typography hierarchy (font families, weights, sizes, line heights), and spacing scale.
  2. Asset Export: Slicing and exporting vector graphics as .svg and photos as optimized .webp or .png into the images/ folder.
  3. HTML Scaffold: Write semantic HTML5 structure (<header>, <main>, <section>, <footer>).
  4. CSS Styling: Define CSS custom properties, apply global resets, and build desktop/mobile layouts using CSS Grid and Flexbox.
  5. Interactive Logic: Add vanilla JavaScript for mobile navigation toggles, modals, and dynamic components.
  6. QA & Optimization: Audit pixel alignment, responsive breakpoints, lighthouse performance, and WCAG accessibility.
Basic
Q2: What are the advantages of SVG format over raster formats (JPG, PNG) for website UI icons and branding assets?
  • Infinite Resolution & Scalability: SVGs are composed of mathematical vectors (points, lines, paths). They never pixelate or blur on ultra-high-DPI (Retina, 4K, 8K) screens.
  • Ultra-Small File Sizes: A crisp vector icon often weighs less than 1-2 KB, drastically speeding up initial page load.
  • CSS Styleability: When embedded inline, SVG shapes can be styled with CSS (e.g. fill: currentColor;, hover color transitions, stroke-width adjustments).
  • DOM & Animation Access: Individual paths within an SVG can be animated using CSS @keyframes or manipulated dynamically via JavaScript.
Basic
Q3: Explain the difference between 1x, 2x, and 3x image asset exports and why high-DPI displays require higher asset resolutions.

Standard 1x Displays: 1 physical device pixel corresponds directly to 1 CSS pixel (Device Pixel Ratio DPR = 1). Standard resolution images look crisp.

Retina / High-DPI Displays (2x, 3x): Devices like modern smartphones, iPads, and MacBooks pack 2 to 3 physical hardware pixels into the physical footprint of a single CSS pixel (DPR = 2 or 3).

Why 2x/3x Assets are Required: If you display a 1x raster image (e.g., 400x300px) on a 2x Retina screen, the display must stretch 400 pixels across 800 physical pixels, resulting in noticeable pixel blur and softness. Exporting at @2x (800x600px) and displaying it at 400x300 CSS pixels provides pin-sharp rendering.

Basic
Q4: How do you inspect padding, margins, and distances between elements in Figma Dev Mode?
  1. Switch Figma to Dev Mode using the toggle switch in the top-right toolbar (or press Shift + D).
  2. Click to select the primary element (e.g., a button).
  3. Hold down the Alt key (Windows) or Option key (macOS) and hover your mouse cursor over an adjacent element (e.g., container card edge or title heading).
  4. Figma displays clear red distance measurement lines and numeric pixel labels indicating exact margins and spacing.
  5. The Dev Mode sidebar displays computed CSS box model measurements (padding, width, height, gap, border-radius).
Intermediate
Q5: A UI designer provides a static desktop mockup with a fixed width of 1440px. How should a front-end developer adapt this into a fluid responsive layout for tablets and smartphones?

Static mockups represent a single snapshot in time. To convert to code:

  • Container Wrapper: Enclose the content in a container with max-width: 1440px; margin-inline: auto; padding-inline: 1.5rem; to prevent unbounded stretching on ultra-wide monitors.
  • Fluid Columns: Convert fixed pixel column widths to percentages, flex ratios, or CSS Grid fr units.
  • Breakpoints: Introduce media queries at standard device viewports (e.g. 1024px for tablet landscape, 768px for portrait tablet, 480px for smartphones).
  • Layout Reorganization: Collapse multi-column desktop grids into a clean single-column vertical flow on mobile screens, and replace horizontal header links with an accessible mobile drawer/hamburger menu.
Intermediate
Q6: How does Figma's Auto Layout relate to CSS Flexbox? Provide a direct comparison of properties.

Figma Auto Layout maps directly to CSS Flexbox properties:

  • Direction: Horizontal → flex-direction: row; | Vertical → flex-direction: column;
  • Item Spacing: Gap between items → gap: [N]px;
  • Padding: Top/Bottom & Left/Right padding → padding: [top]px [right]px [bottom]px [left]px;
  • Alignment: Align items along cross-axis → align-items: center / flex-start / flex-end;
  • Distribution: Distribute along main-axis → justify-content: space-between / center;
  • Resizing: 'Hug contents' → width: max-content; | 'Fill container' → flex: 1; width: 100%;
Intermediate
Q7: How do you implement responsive images using 'srcset' and 'sizes' to serve optimal image sizes across desktop, tablet, and mobile?

Use the srcset and sizes attributes on an <img> element:

<img
  src="images/hero-fallback-800.jpg"
  srcset="images/hero-400.webp 400w,
          images/hero-800.webp 800w,
          images/hero-1200.webp 1200w,
          images/hero-1600.webp 1600w"
  sizes="(max-width: 600px) 100vw,
         (max-width: 1024px) 50vw,
         1200px"
  alt="Team building modern web applications"
  loading="lazy"
  width="1200" height="600">

How it Works: srcset informs the browser of all available asset widths. sizes tells the browser what width the image will occupy in layout at different viewport queries. The browser calculates the screen's DPR and selects the smallest file that will display sharply without wasting user mobile data.

Intermediate
Q8: Explain the difference between self-hosting fonts with '@font-face' versus loading them from Google Fonts CDN.

Google Fonts CDN (External):

  • Pros: Instant implementation via a simple <link> tag; reliable global edge caching.
  • Cons: Third-party network latency; introduces extra DNS lookups and TLS handshakes; potential GDPR privacy compliance issues in the EU.

Self-Hosting Web Fonts (Local WOFF2):

  • Pros: Maximum performance when combined with HTTP/2 multiplexing (downloaded over the same connection as HTML/CSS); 100% GDPR compliant; immune to CDN outages.
  • Cons: Developer must convert font files to .woff2, write @font-face declarations, and configure server font caching headers.
Advanced
Q9: What is 'Flash of Invisible Text' (FOIT) and how does 'font-display: swap' solve font rendering performance during web page loading?

FOIT (Flash of Invisible Text): Occurs when a browser hides text content while downloading external custom web fonts over the network, leaving users staring at blank spaces for several seconds.

Solution with font-display: swap:

@font-face {
  font-family: 'Inter';
  src: url('fonts/inter.woff2') format('woff2');
  font-weight: 400;
  font-display: swap; /* Instantly renders fallback font */
}

Instructs the browser to immediately render readable text using an installed system fallback font (e.g. Arial, sans-serif). Once the custom .woff2 font finishes downloading, the browser smoothly swaps it in, preventing blocked user interaction and passing Core Web Vitals (FID/INP).

Advanced
Q10: Explain how to eliminate Cumulative Layout Shift (CLS) when swapping custom web fonts using modern font metric override properties.

When font-display: swap replaces a system fallback font with a custom web font, a noticeable layout jump (CLS) occurs if the fallback font has differing glyph widths, line heights, or ascender/descender heights.

Solution with CSS Font Metric Overrides:

/* Declare modified fallback font */
@font-face {
  font-family: 'FallbackInter';
  src: local('Arial');
  ascent-override: 90%;
  descent-override: 22%;
  line-gap-override: 0%;
  size-adjust: 107%; /* Scales Arial glyphs to match Inter exactly */
}

body {
  font-family: 'Inter', 'FallbackInter', sans-serif;
}

size-adjust scales the fallback font's bounding boxes so words occupy the exact same physical space as the custom font, reducing font-swap CLS score to near zero.

Advanced
Q11: Why is 'Pixel-Perfect' implementation considered a flawed objective when translating desktop Figma mockups into modern multi-device web applications?

Why Pixel-Perfection Fails on the Real Web:

  • Infinite Viewport Fragmentation: Devices range from 320px mobile screens to 5120px 5K displays with varying aspect ratios (16:9, 19.5:9, 21:9). A static 1440px design cannot look identical on all displays.
  • Operating System Font Rendering Differences: macOS uses Core Text (bolder, rounded subpixel antialiasing), Windows uses DirectWrite/ClearType (sharper, thinner stems), and Linux uses FreeType. Text lengths vary across platforms.
  • User Accessibility Settings: Visually impaired users increase system default font sizes or browser zoom to 150%. Rigid pixel containers clip and break text.
  • Fluid Adaptation Goal: Modern web engineering prioritizes Design Intent, fluid proportional balance, harmonious typographic scales, and bulletproof accessibility over brittle pixel-perfection.
Advanced
Q12: What end-to-end Quality Assurance (QA) checklist should a developer complete before delivering a coded website converted from a design mockup?

Comprehensive Design-to-Code QA Checklist:

  1. Visual Fidelity: Compare side-by-side with Figma mockup across typography, color palettes, button active/hover states, drop shadows, and border radii.
  2. Responsive Verification: Test smoothly at 360px (mobile), 768px (tablet portrait), 1024px (tablet landscape/laptop), 1440px (desktop), and 1920px (large monitor). Ensure zero horizontal overflow scrolling.
  3. Cross-Browser Testing: Validate rendering and functional behavior across Chromium (Chrome/Edge), Gecko (Firefox), and WebKit (Safari on macOS and iOS).
  4. Accessibility Audit (WCAG 2.1 AA): Run automated checks for contrast ratios (≥ 4.5:1), keyboard Tab navigability, focus rings, and proper ARIA tags.
  5. Performance Audit (Google Lighthouse): Achieve 90+ score across Performance, Accessibility, Best Practices, and SEO. Verify all images are WebP/SVG with explicit width/height dimensions.
